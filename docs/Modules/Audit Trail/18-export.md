# Export & Import Specification

## Overview
Defines export formats, signing, verification, import for migration, and regulatory submission requirements.

---

## Export Formats

### Format 1: CSV (Data Exchange)

#### File Structure
```
audit-export-{request_id}-{timestamp}.csv
audit-export-{request_id}-{timestamp}.sha256
```

#### CSV Columns (Order Fixed)
| Column | Type | Description |
|---|---|---|
| sequence_number | BIGINT | Global monotonic sequence |
| timestamp | ISO8601 UTC | Microsecond precision |
| actor_user_id | UUID | NULL for SYSTEM |
| actor_name | VARCHAR | User full name |
| actor_email | VARCHAR | User email |
| actor_type | Enum | USER, SYSTEM, SCHEDULED |
| action | Enum | CREATE, UPDATE, DELETE, TRANSITION, SIGN, VIEW_SENSITIVE, FIELD_CHANGE |
| module | Enum | RECEIVING, SAMPLING, ANALYSIS, CERTIFICATE, RELEASE, USER_MGMT, SECURITY, WAREHOUSE, MONOGRAPH, SYSTEM |
| entity_type | VARCHAR | e.g., MaterialBatch |
| entity_id | UUID | |
| field_name | VARCHAR | NULL except FIELD_CHANGE |
| old_values | JSON | Full object or changed fields |
| new_values | JSON | Full object or changed fields |
| correlation_id | UUID | |
| session_id | UUID | |
| ip_address | VARCHAR | IPv4/IPv6 |
| user_agent | TEXT | |
| previous_hash | CHAR(64) | SHA-256 hex |
| event_hash | CHAR(64) | SHA-256 hex |
| signature_user_id | UUID | From digital_signature |
| signature_timestamp | ISO8601 | From digital_signature |
| signature_meaning | TEXT | From digital_signature |
| signature_type | Enum | SHARED_SECRET_TOTP, SHARED_SECRET_STATIC |
| signature_verification | Enum | VERIFIED, FAILED, NOT_APPLICABLE |
| signed_data_hash | CHAR(64) | From digital_signature |

#### CSV Encoding
- UTF-8 with BOM
- RFC 4180 compliant
- Fields containing comma, newline, or double-quote → double-quoted
- Double-quotes escaped as `""`
- Null values → empty field (not "NULL")

#### Checksum File (.sha256)
```
a1b2c3d4e5f6...  audit-export-abc123-20240115T103000.csv
```
- Single line: `<sha256_hex>  <filename>`
- Verifiable with `sha256sum -c`

### Format 2: PDF (Regulatory Submission)

#### File Structure
```
audit-export-{request_id}-{timestamp}.pdf
```

#### PDF Structure
1. **Cover Page**
   - Mini-LIMS Audit Trail Export
   - Export ID, Request ID
   - Date Range, Filters Applied
   - Generated By, Generated At
   - Total Records
   - File SHA-256
   - Digital Signature Block (PAdES)

2. **Table of Contents**
   - By Module
   - By Date
   - By Entity

3. **Events Section** (per module, chronological)
   - Module header
   - Table: Sequence, Timestamp, Actor, Action, Entity, Field, Changes, Signature
   - Page breaks at module boundaries

4. **Integrity Verification Summary**
   - Verification Status: PASSED/FAILED
   - Events Verified
   - Mismatches (if any)
   - Verification Hash
   - Verified By, Verified At

5. **Signature Manifestations** (per 21 CFR 11.50)
   - List of all SIGN events with:
     - Printed Name
     - Date/Time
     - Meaning
     - Signature Type
     - Verification Status

6. **Appendix: Export Metadata**
   - Complete filter criteria
   - Export configuration
   - System version

#### PDF Digital Signature (PAdES)
- **Standard**: ETSI EN 319 142 (PAdES-B-LTA)
- **Certificate**: Organization-issued code signing cert
- **Timestamp**: RFC 3161 trusted timestamp authority
- **Long-term Validation**: OCSP/CRL embedded
- **Visible Signature**: On cover page with cert details

#### PDF Accessibility
- Tagged PDF (PDF/UA)
- Searchable text (no scanned images)
- Bookmarks for navigation

## Export Generation Process

### EXP-PROC-001: Request Validation
1. Validate date range (≤ 1 year default, configurable)
2. Estimate record count via `COUNT(*)` with filters
3. If estimate > 10,000 → require approval
4. Create `audit_exports` record: PENDING or PENDING_APPROVAL

### EXP-PROC-002: Approval Workflow
1. Notification to authorized approvers (QC Manager)
2. Approver reviews: date range, filters, estimated size
3. Approver applies electronic signature
4. Status → APPROVED → GENERATING

### EXP-PROC-003: Generation (Background Job)
1. Query events with filters (cursor-based for memory)
2. **CSV**: Stream write to temp file, compute SHA-256 incrementally
3. **PDF**: Build with ReportLab/WeasyPrint, sign with PAdES
4. Upload to object storage (S3/MinIO/Azure Blob)
5. Compute final file hash
6. Update `audit_exports`: COMPLETED, file_path, file_hash, record_count

### EXP-PROC-004: Failure Handling
- On error: status = FAILED, error_message populated
- Cleanup temp files
- Notify requestor
- Retry: New export request (idempotent)

## Export Security

### EXP-SEC-001: Access Control
- Export requires `AUDIT_EXPORT` permission
- Download requires ownership OR `AUDIT_EXPORT` + approval
- PII fields (actor_name, actor_email, ip_address, user_agent) only if `AUDIT_VIEW_PII`

### EXP-SEC-002: Data Protection
- Export files encrypted at rest (SSE-S3 or customer-managed keys)
- TLS for download
- Signed URLs with 1-hour expiry
- Audit log: export download recorded

### EXP-SEC-003: Integrity
- CSV: SHA-256 checksum file
- PDF: PAdES digital signature
- Export record stores `file_hash` for later verification
- Verification endpoint: `GET /exports/{id}/verify`

## Import Specification (Migration/Recovery)

### IMP-SPEC-001: Import Use Cases
1. **Migration**: Move audit events between environments
2. **Recovery**: Restore from backup after data loss
3. **Consolidation**: Merge audit trails from multiple instances

### IMP-SPEC-002: Import Format
- Same CSV format as export
- Must include all columns
- `sequence_number` must be globally unique (or offset provided)
- Hash chain must be valid (verified before import)

### IMP-SPEC-003: Import Process
1. **Pre-validation**:
   - Parse CSV, validate schema
   - Verify hash chain continuity
   - Verify no sequence conflicts with existing data
   - Check digital signatures valid
2. **Dry-run**: Report conflicts, gaps, mismatches
3. **Import** (System Admin only):
   - Disable audit writes (maintenance mode)
   - COPY into `audit_events` (bypass trigger? No - trigger must run)
   - Alternative: Use `pg_restore` for partition-level
   - Re-enable audit writes
4. **Post-import verification**: Full hash chain check

### IMP-SPEC-004: Import Constraints
- Cannot import into partition with existing data
- Best practice: Import into new partition range
- Sequence numbers: Use offset or reserve range
- Signatures: Preserved but marked as `imported: true`

## Regulatory Submission Package

### REG-PKG-001: FDA 21 CFR Part 11 Inspection Package
For regulatory inspection, provide:
1. **Signed PDF Export** of relevant date range/entity
2. **Integrity Verification Report** (signed PDF)
3. **Retention Policy Document** (this spec)
4. **Access Control Matrix** (Security Rules)
5. **Disposal Authorization Records** (if any)
6. **Legal Hold Records** (if any)
7. **System Validation Summary** (test reports)

### REG-PKG-002: Package Assembly
- All documents in PDF/A-2b (archival)
- ZIP with manifest (SHA-256 per file)
- Manifest signed with org certificate
- Delivered via secure channel (encrypted email, secure portal)

## Configuration

### Export Configuration (Database)
```sql
CREATE TABLE export_config (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    max_records_without_approval INTEGER NOT NULL DEFAULT 10000,
    max_date_range_days INTEGER NOT NULL DEFAULT 365,
    pdf_signing_cert_id VARCHAR(100), -- Reference to cert in vault
    csv_delimiter CHAR(1) NOT NULL DEFAULT ',',
    pdf_template_version VARCHAR(20) NOT NULL DEFAULT '1.0',
    storage_bucket VARCHAR(200) NOT NULL,
    storage_encryption_key_id VARCHAR(100),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_by UUID REFERENCES users(id)
);
```

### Retention for Exports
- Export files retained per module retention policy
- Export metadata (`audit_exports`) retained 7 years minimum
- Disposal follows same dual-authorization process

## Testing Requirements

### EXP-TEST-001: Export Correctness
- Export 100 events → verify all 100 in CSV/PDF
- Filters correctly applied
- Hash chain values present
- Signature data present

### EXP-TEST-002: Export Integrity
- CSV checksum matches file
- PDF signature validates (cert chain, timestamp)
- Export record `file_hash` matches actual file

### EXP-TEST-003: Export Authorization
- Unauthorized user → 403
- Large export without approval → 409 PENDING_APPROVAL
- Approval by correct role → proceeds

### EXP-TEST-004: Import Validation
- Valid CSV → passes dry-run
- Broken hash chain → fails dry-run
- Sequence conflict → fails dry-run
- Successful import → events queryable, chain valid

### EXP-TEST-005: Regulatory Package
- Package assembles all required documents
- Manifest signatures valid
- Files open correctly in standard viewers
